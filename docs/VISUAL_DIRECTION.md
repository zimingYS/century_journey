# Century Journey 视觉方向基线

## 1. 决策

《Century Journey》的视觉身份确定为：

> **文明演进 + 荒野旅程的沙盒模拟像素风格生存游戏。**

视觉目标不是单纯复刻 Minecraft，也不是追求写实 3D，而是把低多边形体素世界、像素纹理、年代变化和玩家旅程组合成一个有明确记忆点的风格。

这份文档作为后续世界渲染、角色、HUD、菜单、物品图标、音效反馈和宣传截图的共同基线。新功能如果无法服务于这条身份，应降低优先级或重新设计。

## 3. 画面构造

### 3.1 世界画面

- 画面主体是玩家正在经历的荒野，而不是抽象的测试平面。
- 前景、中景、远景必须有层次：可交互资源、地形/植被群落、山脉/河流/聚落或文明遗迹。
- 通过日夜、季节、天气和生态群落表达“世界在变化”。这些系统可以分阶段实现，但画面接口应预留状态变化。
- 保留体素边缘和像素纹理的清晰度，避免过度模糊、过度景深和纯粹依赖后处理制造高级感。
- 光照应优先保证角色、方块和可交互目标的可读性。背光时必须有环境补光，不能让角色变成纯黑剪影。
- 每个生物群系需要至少拥有一组色彩、地表细节、植被轮廓和环境声音差异。

### 3.2 文明演进的视觉表达

文明演进不是只显示一个年份数字，而应逐步体现在：

- 建筑材料：原始木石 -> 加工木材/砖石 -> 金属和更复杂的设施。
- 聚落结构：营地 -> 村落 -> 城镇/交通网络 -> 具有历史痕迹的区域。
- 工具和装备：外形、材质、耐久反馈和 UI 图标随着时代变化。
- 世界记忆：火灾、干旱、洪水、迁徙、遗迹和玩家建造物留下可见线索。
- UI 时间线：季节、年份、事件和发现应能形成一条可回顾的旅程记录。

### 3.3 玩家旅程的镜头语言

- 第一人称用于采集、建造和战斗，强调手部动作、命中点和材质反馈。
- 第三人称用于展示角色、地形和旅程成果，角色轮廓必须清楚。
- 重要发现使用短暂的镜头、环境声或 UI 记录反馈，不用长时间打断操作。
- 远景应让玩家知道“下一步可以去哪里”，而不是只承担背景填充。

## 4. UI 视觉语言

### 4.1 核心气质

UI 采用“旧时代探险记录板 / 工坊仪表盘”的方向：深色金属或木石框架、暖色金属边缘、清晰的像素图标、低饱和背景和少量高亮状态色。

它应同时传达两件事：

1. 这是一个可以操作的模拟工具。
2. 这是一个记录玩家历史的旅程界面。

### 4.2 颜色规则

- 基础层：炭黑、深灰、低饱和蓝灰或木石棕。
- 主强调色：暖金或琥珀，用于选中、重要进度、时间线和文明里程碑。
- 正向状态：低饱和绿色，用于可用、完成、资源充足。
- 危险状态：红色，仅用于生命危险、错误和不可逆操作。
- 信息状态：蓝色，仅用于天气、环境、知识或提示。
- 同一个控件状态只使用一种主强调色，避免蓝、青、黄、橙、绿同时争夺注意力。

### 4.3 面板和控件

- 面板边框应有轻微材质层次，但不能让装饰压过信息。
- 控件需要明确区分普通、悬停、按下、选中、禁用和焦点状态。
- 选中状态优先使用边框、底色和图标变化组合，不依赖单一亮色。
- 面板打开、关闭、切页和悬停反馈使用短过渡；目标时长约 80-180ms，不能拖慢操作。
- 创造模式保持“左侧分类 + 中央网格 + 右侧最近使用/功能区 + 底部快捷栏”的结构。
- 生存背包保持“角色/装备 + 属性 + 合成 + 背包”的结构，但需要更强的装备槽图标、物品状态和拖放反馈。
- 所有面向玩家的文本必须使用正式名称；内部 ID 如 `axe`、`grass_like`、`pickaxe` 不得直接显示。

### 4.4 信息密度

- 重要信息在第一眼可读：生命、饥饿、当前工具、目标方块、天气和时间。
- 次要信息通过提示、详情面板或历史记录展开。
- 不在世界画面常驻大面积说明文字；让图标、颜色、声音和短提示承担反馈。
- UI 缩放必须保持布局稳定，窗口尺寸变化不能导致槽位、按钮或文本重叠。

## 5. 动画、音效和反馈目标

### 动画

- 角色动画优先服务于重量感和动作节奏：待机呼吸、走跑摆臂、跳跃起落、挖掘蓄力/命中/回收、攻击前摇/命中/收招。
- 动作标记必须和伤害、方块操作、粒子和音效同步，不能只改变模型姿势。
- 第一人称手部需要独立的动作曲线和轻微镜头反馈。
- UI 动画只做信息强调，不使用持续闪烁或大幅弹跳。

### 音效

- 按 UI、打开/关闭面板、错误、确认、物品移动都应有明确但克制的反馈。
- 脚步、挖掘、放置、命中、落地按材质分类，并保持随机变体。
- 环境音按生物群系、天气、昼夜和距离分层。
- 预留主音量、音乐、环境、效果和 UI 音量的独立设置；没有音乐时也不能让环境声承担音乐的职责。

### 视觉反馈

- 方块挖掘需要清晰的分阶段裂纹、粒子和命中音。
- 受伤、饥饿、低温/环境危险等状态要有可辨识的短反馈。
- 物品拾取、制作完成、发现历史事件应通过图标、短文本和声音形成闭环。

## 6. 当前实现与目标的差距

当前项目已有可复用基础：程序化体素世界、昼夜/天空、角色分层动画、动作标记、粒子、空间音频、材质脚步声、统一 UI 主题、工具提示、库存拖放和导航状态。

当前最需要补齐的不是更多底层系统，而是表现层的一致性：

- 世界的地表、植被和远景仍然重复，缺少文明与历史的可见线索。
- 背光角色的可读性不足，第一/第三人称角色轮廓和服装需要强化。
- UI 仍偏平直矩形，强调色和材质语言尚未统一。
- 菜单与暂停界面在大分辨率下留白过多，内部物品标签仍可能暴露。
- 音频已有事件覆盖，但素材数量、环境层和音乐不足。
- 交互功能较完整，但过渡动画、命中反馈和操作重量感不足。

## 7. 分阶段落地顺序

### 阶段 A：建立基准画面

选择一个森林-河流-海岸场景，固定一个目标分辨率和时间段，完成：曝光、环境补光、地表变化、树木轮廓、雾和角色可读性。

### 阶段 B：建立 UI 基线

统一颜色 token、边框材质、字体层级、控件状态和过渡时长；先改创造模式、暂停菜单和生存背包三类高频界面。

### 阶段 C：建立反馈闭环

优先完成挖掘、放置、攻击、拾取、制作和脚步的动画-粒子-音效同步。

### 阶段 D：加入旅程和文明记忆

加入年份/季节/事件记录、发现提示、聚落或遗迹视觉层，并让 UI 时间线与世界状态互相呼应。

### 阶段 E：扩展内容密度

再增加更多生物群系、建筑、天气、环境音和时代资产。内容数量应服从风格一致性。

## 8. 验收标准

一个新玩家看到截图或运行 30 秒后，应能回答：

- 这是体素沙盒，但不是普通的 Minecraft 复刻。
- 这个世界正在经历季节、时代或历史变化。
- 玩家是在一片可以探索和改造的荒野中旅行。
- UI 能让人快速理解装备、资源、环境和下一步行动。

内部验收时，优先检查以下问题：

- 背光角色是否仍然可辨认。
- 选中控件是否只有一个明确视觉焦点。
- 动作命中点、粒子和音效是否同一时刻发生。
- 世界是否存在近景、中景、远景和至少一种历史/文明线索。
- 任意界面是否出现内部 ID、文本重叠、过度留白或无法解释的颜色。

## 9. 一句话原则

> **让玩家看到一个会随着时间改变的世界，并让每个 UI 和反馈都像一页正在写下的旅程记录。**

## 10. 实施记录

### 2026-07-20：光照与世界可读性第一轮

已完成：

- 提高白天和夜间环境补光，降低直射太阳光强度，改善背光角色与树叶可读性。
- 收窄曝光变化范围，启用高斯阴影过滤，并把阴影覆盖距离扩展到主要可视区域。
- 增加随昼夜变化的距离雾，让区块边界、地平线和远景自然融合。
- 将大气环境贴图用于更强的漫反射补光，并提高近距离大气层次采样质量。
- 重做太阳程序纹理：由方形橙红硬边改为圆形暖白核心和克制光晕。
- 下压水面并调整为更冷、更透明的材质，使沙岸露出明确高度差。
- 对官方沙地和树叶纹理执行非破坏性色彩校正；自定义内容纹理不受影响。
- 扩展自动截图检查，可选择已有世界、配置等待时间，并稳定第三人称镜头位置。

后续仍需单独处理：水面动画与岸边泡沫、生物群系差异化雾色、天气云层、远景文明地标，以及角色材质和服装轮廓。
